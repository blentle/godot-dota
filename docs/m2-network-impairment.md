# 本机 UDP 网络故障验证

本切片在客户端与服务器之间加入测试专用 UDP 转发器，在 ENet 接收之前注入故障。它不修改 JSON 消息，也不通过慢服务器代替真实数据报丢弃；客户端与服务端继续使用原来的可靠 ENet 协议。

## 运行

```sh
python3 tools/test_shared_pair.py --godot /实际路径/Godot --players 4 --impaired
```

`tools/check_project.py --network` 同时执行此测试、正常双玩家/四玩家场景以及原有独立会话网络测试。

每个客户端有独立的本机转发端口和上游套接字。服务器仍看到不同的传输连接，控制权、就绪和资源隔离不能依赖所有客户端共用一条连接。

## 故障模型

- 上行与下行各自计数，每个数据报基础延迟 40 毫秒，确定性抖动 ±20 毫秒；额外往返延迟约 80 毫秒。
- 每第 17 个数据报丢弃一次，约 5.9%；每第 23 个未被丢弃的数据报复制一次，副本晚 3 毫秒。
- 按交付时间排序转发，抖动可能造成 UDP 数据报乱序；具体乱序数量未作为验收指标。
- 故障作用于 UDP 数据报，包括 ENet 握手、确认与重传。它不是按游戏命令计算的丢失率；重传本身也可能被注入故障。
- 随机数不参与策略，但操作系统调度仍会影响数据报数量。测试要求每个客户端双向均实际出现丢弃、重复和成功转发，否则不能通过。
- 转发队列上限 4096；队列超限或套接字错误使测试失败，不通过静默丢弃改变故障模型。工具退出时关闭所创建的线程、套接字及 Godot 子进程。

## 验证边界

四个独立客户端必须完成真实战场装配、全员就绪、各自购买与移动、观察全部英雄及召唤物；至少三个共同 tick 的公共单位摘要在所有客户端中一致。最后确认旧局清理后的新客户端等待状态。该清理检查直接连接服务器，不声称经过故障链路。

策略单元测试验证固定序列、延迟边界、丢弃与重复冲突时的优先级和非法参数。转发器不写入正式客户端或生产服务器启动流程。

尚未覆盖长时间高丢包、带宽限速、网络分区、重连、十人完整比赛、互联网环境和三平台混合对战。快照仍全部可靠发送，本测试成功不代表已解决高延迟下的队头阻塞或完成性能验收。
