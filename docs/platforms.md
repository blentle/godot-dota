# 三平台交付矩阵

用户于 2026-10-06 确认：Windows、macOS、Linux 全部需要。

| 产品 | Windows | macOS | Linux |
|---|---|---|---|
| 游戏客户端 | x86_64 | arm64 + x86_64 | x86_64 |
| 平台启动器 | x86_64 | arm64 + x86_64 | x86_64 |
| 生产对战服务器 | 不作为首发部署目标 | 不作为首发部署目标 | x86_64 headless |

架构与最低系统版本在实际测试后冻结；不能将导出成功视为平台支持完成。macOS Intel 若无测试设备，须明确记为未实机验收。

## 实现约束

- 同一 GDScript 代码、协议版本与内容包；平台差异集中到启动、IPC、更新和用户目录适配层。
- 游戏内使用 Godot 文件路径 API，存档和设置写入用户数据目录。禁止硬编码盘符、反斜杠路径、大小写不一致的资源名。
- 启动器启动 .exe、macOS app 内可执行文件或 Linux 可执行文件；使用参数数组，验证安装根路径与构建哈希。
- IPC 后续实现 Windows 命名管道或受限本地连接，以及 macOS/Linux Unix socket 或受限本地连接；令牌交接使用随机挑战与单次兑换。不能仅凭 localhost 就信任调用方。
- 更新按 OS/CPU 选择程序包，内容包共用；更新失败可回滚，运行中的二进制不直接覆盖。Windows 文件锁与 macOS app bundle 分别处理。
- 先用 Compatibility 渲染器建立兼容性基线，具体驱动、最低系统与性能目标经三平台场景测试后公布。
- 快捷键考虑 macOS 系统保留组合；高 DPI、窗口焦点、鼠标捕获、全屏切换、中文字体与输入单独验证。

## 发布验收

三平台分别验证安装、首次启动、登录、更新、匹配、拉起游戏、退出回大厅和重连。至少一局包含三种系统的 10 个客户端，必须内容一致、战果一致。Linux 桌面验证 X11/Wayland 目标环境；macOS 验证签名与公证后的安装包；Windows 验证签名安装包。签名身份与发布凭据在发布阶段配置。
