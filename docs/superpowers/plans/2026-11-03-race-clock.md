# 原始种族时钟实施计划

> 执行要求：使用 superpowers:executing-plans 逐项实施，复选框记录实际完成情况；如用户另选子代理方式，则使用 superpowers:subagent-driven-development。

**目标：** 按原始 UI 配置加载 NightElf、Undead、Human 对应时钟模型，删除手工替换边框。

**架构：** 保留现有时钟组件及 HUD 节点，以固定种族表选择原始模型；组件独立处理绑定成功/失败、切换和暂停。已有下载转换工具补齐资源，不新建加载框架。

**技术栈：** Godot 4.7.2、GDScript、现有 Node/Python 资源工具，无新增依赖。

**设计：** `docs/plans/2026-11-03-race-clock-design.md`，用户已批准。

## 全局约束

- 固定 1024×768，Clock 区域 (435,-7)–(589,70)，不修改其他 HUD 布局。
- 原始纹理、最近邻、透明独立视口、无抗锯齿；保留暂停与确定时间采样。
- 单个自有源码文件不超过 500 行；注释、设计及验收记录使用中文。
- 不新增昼夜规则或 Orc 控制台，不改变权威状态；不把字段相等当成实际模型加载验证。
- Windows/Linux、真实时间映射、精确混合与原版像素验收保持明确边界。

## 审查重点

1. 无效或缺失模型：清除旧视图后不得访问未完成的数据，静态回退也不能继续推进动画。
2. 相同种族重复配置：保留同一模型实例及动画时间，避免每次 HUD 刷新归零。
3. 跨种族切换或重绑：实际 Source、材质及模型数量正确，不能保留旧框覆盖。
4. 暂停时切换种族：暂停标志不丢失，恢复后继续推进，零推进不变化。
5. 原模型取景不同：比较实际几何范围，再判断是否共用相机；截图不得只有空白或背面。
