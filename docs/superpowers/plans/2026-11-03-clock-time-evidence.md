# 地图时间证据提取实施计划

> 执行要求：使用 superpowers:executing-plans 按任务实施；复选框记录实际进度。

**目标：** 静态提取地图时间调用、归属及上下文，建立可追溯证据报告，不执行 JASS 或改动游戏规则。

**架构：** 用小型词法扫描器区分代码、注释和字符串，提取函数及相关调用；独立报告入口校验输入摘要、关联上下文并输出 JSON 与中文说明。不构建完整 JASS 解释器，不把静态引用当成可达性证明。

**技术栈：** Python 标准库，现有提取脚本和原始模型 JSON；无新增依赖。

**设计依据：** `docs/plans/2026-11-03-clock-time-evidence-design.md`，用户已批准。

## 全局约束

- 所有文档、源码注释与测试说明使用中文；技术标识和源代码引文保留原文。
- 每个自有源文件不超过 500 行，词法解析与报告生成分离。
- 只读源地图及提取文件，不执行地图函数，不更改游戏和服务器状态。
- 使用已记录地图 SHA-256；报告记录提取文件摘要、正规化行号及不确定项。

## 审查重点

1. CR、LF、CRLF 混用不能造成函数归属和行号错乱。
2. 注释、字符串或相似函数名中的文本不能误算为真实调用。
3. 嵌套 if/elseif/else 上下文必须保留，不能只摘最近一行当完整触发条件。
4. 混淆变量、动态调用或缺失引用必须标记待核对，不推断技能或模式名称。
5. 源摘要不符时必须拒绝生成正式报告，不能沿用旧报告暗示成功。
