# 十席 5v5 开发对局

共享开发服务器支持 2、4、10 个席位，默认两席。十席按连接顺序交替分配两个阵营，每队五个不同出生点；所有席位装配战场并发送就绪后才推进模拟。开发构建标识为 `m2-network-9`。

## 运行

```sh
godot --headless --path game --script res://tests/network_server.gd -- --port=27883 --shared --players=10
```

分别启动十个客户端：

```sh
godot --path game -- --connect-local=27883
```

工具自动启动一个服务器与十个独立客户端，并在最初操作完成后持续运行至少 60 秒模拟时间：

```sh
python3 tools/test_shared_pair.py --godot /实际路径/Godot --players 10 --soak-seconds 60
```

`--soak-seconds` 范围为 0～300，表示额外观察的模拟时间，不是加速倍率。各客户端仍装配真实战场、HUD 和远程世界，但默认无窗口运行；不能以此替代窗口性能和三平台验收。

## 验证层次

- 权威席位测试同时覆盖四席与十席：欢迎包身份、出生点通行、基地购物、人数屏障、超额连接拒绝、重复交易、伪造席位、控制隔离、断线与新局配置。
- 十席五分钟规则模拟按 60 Hz 加速推进，验证共享时钟、收入、兵线波次、召唤生命周期、单位/弹道边界、快照体积与所有接收者公共状态一致。英雄设置为无敌测试夹具，以隔离状态清理与游戏平衡；它不是正常游戏整局。
- 十客户端持续联机使用真实 ENet 连接，各自购买、移动、召唤、每五秒发送保持命令并等待确认；持续运行后检查召唤过期和兵线推进。所有客户端公共单位摘要按共同 tick 比较，最后验证新局等待与旧局清理。

原有四玩家故障链路验证保留。`--impaired` 可以与人数参数组合，但只有实际运行的组合才能标记已验证。

原席位短时重连已在双客户端网络分区中验证，详见 m2-reconnect.md；十席同时重连尚未验收。

## 与完整 M4 的差距

此切片不包含平台真实账号、匹配、启动票据、正式英雄、战争迷雾、服务器重启恢复、掉线判负、战果上传、完整胜负长局或三平台混合比赛。身份仍为本机开发连接；服务仅绑定回环地址。十个测试进程不代表十个真实账号已经经平台进入正式比赛。

## 载荷与失败处理

首轮十客户端测试暴露 ENet `Sending failed!`，随后服务器传输实例关闭。应用层改为在 ENet 分片前压缩大 JSON 快照：小于 1024 字节的消息仍为原始 JSON；大包使用 `DZ01` 标记、四字节原始长度和 Zstandard 数据。声明长度及实际输入限制为 262144 字节，解压前检查边界；解码后仍只接受 JSON 字典，不反序列化对象。

`packet_codec.gd` 独立负责载荷编码，命令上行保持原有小 JSON 协议。引擎解压接口使用预先限制的缓冲区大小，参见 [Godot PackedByteArray 官方文档](https://docs.godotengine.org/en/stable/classes/class_packedbytearray.html#class-packedbytearray-method-decompress)。传输实例关闭后服务端停止轮询并释放会话，避免继续向失效连接发送或刷错误日志。

macOS Apple Silicon 首次采用压缩后的十一进程持续联机取得 627 个共同 tick 的一致公共单位摘要；五分钟加速规则测试也通过。此结果仅支持本机开发验证，不推断真实网络吞吐上限，也不宣称所有发送失败的底层原因都已消除。

后续全员断网开发的回归再次触发发送失败，说明仅压缩不足以保证稳定。现由 `snapshot_dispatch.gd` 保存采集时的编码载荷，每帧最多发送两个席位；采集仍保持原频率和共同 tick，分批期间的世界变化不会改变已采集状态。发送节奏单测同时覆盖失败席位隔离。
