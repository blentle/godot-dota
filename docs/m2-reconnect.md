# 开发局网络分区与重连

当前支持运行中的单席位短时恢复，前提是至少仍有一名参与者在线。构建标识为 `m2-network-8`。这些凭据仅用于本机开发局，不替代平台账号、启动票据、TLS 或正式身份认证。

## 服务端边界

- 首次握手为每个席位创建 32 字节随机凭据，只在该席位欢迎包中发送，保存在双方进程内存中；不写日志、文件或进程参数。
- 网络断开后保留原会话、已执行命令序号、英雄和私有账本，凭据可在服务器确认断开后的 30 秒内恢复。游戏世界继续运行，断线英雄停止当前订单，仍可受伤、复活和获得符合规则的经验。
- 新连接上报版本、内容清单、当前开发局和凭据，不能指定席位或英雄。校验通过后原会话绑定新连接；即使旧连接尚未超时，它也立即失去命令权限。旧连接随后迟到的断开事件不影响新连接。
- 凭据在本局保留期内可重试，不随每次连接轮换，避免欢迎包丢失后无法恢复；持有该凭据即具有对应开发席位的恢复权。未知、到期和旧局凭据拒绝恢复。
- 开局前仍使用取消装载策略，不支持重连。全员离开立即释放开发局与所有凭据；全员网络分区恢复尚未实现。
- 到期席位不能被无凭据新玩家接管；其英雄仍留场，尚无掉线判负或机器人接管。

## 客户端恢复流程

运行中发现连接断开或五秒没有服务端消息，客户端冻结远程世界和战场输入，显示恢复状态。每三秒尝试新连接，总恢复窗口 25 秒；版本、凭据等明确拒绝或最终超时后提供返回入口。

恢复欢迎包包含原英雄及权威已执行序号。客户端丢弃未确认意图，不自动重发购买或技能；服务端已经完成的交易保留，未到达的交易不会补做。收到恢复后的完整快照才重新开放操作，下一命令使用权威序号加一。

恢复时清理插值缓存与断线期间的旧表现事件；英雄死亡、位置、装备、资源和结果以新快照为准。如果离线期间已经结束对局，恢复快照进入结算。

## 验证

```sh
godot --headless --path game --script res://tests/test_reconnect.gd
python3 tools/test_reconnect_pair.py --godot /实际路径/Godot
```

规则测试覆盖未知/伪造凭据、未开局恢复、旧连接撤权、迟到断开、已成交交易幂等、30 秒边界、恢复原世界、全员释放和跨局拒绝。

真实进程测试启动两名客户端，对其中一人的双向 UDP 入口完全隔离 12 秒，另一人保持在线；恢复后检查原英雄、原装备、未送达交易不重放、序号对齐、新交易及移动恢复。转发器要求实际丢弃数据报，在线客户端需要证明自己的世界持续推进。

尚未完成所有玩家同时断网、服务器重启恢复、凭据持久化、十席同时重连、互联网或三平台混合网络分区验收。
