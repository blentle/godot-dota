# 同一世界共享开发对局

默认模式提供本机回环的一对一开发对局；四玩家 2v2 的启动与验收见 [四玩家说明](m2-four-player.md)。十席模式见 [十席说明](m2-ten-player.md)。默认模式中：第一个连接分配近卫英雄，第二个连接分配天灾英雄。双方共享实体、兵线、建筑、弹道、时间和基地胜负；不再为每个连接分别创建世界。仍使用训练角色和开发数值，不属于正式 DotA 英雄或十人对战。

## 运行

先启动共享服务端，再分别启动两个游戏客户端：

```sh
godot --headless --path game --script res://tests/network_server.gd -- --port=27883 --shared
godot --path game -- --connect-local=27883
godot --path game -- --connect-local=27883
```

每个客户端在自己的基地出生，镜头对准自己的英雄。HUD 标明“多人开发对局”及自己的阵营，商店与背包随玩家切换。右键可以攻击对方英雄；Q/W/E、购买、出售和召唤继续经过服务器校验。图形入口固定使用近战卫兵。

双方客户端完成战场装配并发送就绪后才开始模拟。等待界面显示连接和就绪人数；等待期间时间、金币与单位状态冻结，首波单位预先创建但不行动。尚无选人倒计时和身份认证。超过配置席位数的连接被拒绝。服务仅监听本机，普通 `--server` 入口仍不提供生产服务。不加 `--shared` 时保留原有独立训练会话模式。

## 模块责任

| 模块 | 职责 |
| --- | --- |
| `simulation/shared_match.gd` | 唯一共享世界，战斗、兵线和弹道每步只推进一次 |
| `simulation/player_combat.gd` | 固定玩家英雄的战斗视角，共用规则与实体，隔离金币和战绩 |
| `simulation/training_world.gd` | 玩家订单、导航、经济、技能和召唤控制器；共享模式单独推进订单 |
| `network/shared_authority.gd` | 按配置分配席位、连接绑定、公共时钟、断线策略和最终释放 |
| `network/match_lobby.gd` | 可配置席位表、就绪幂等、等待/装载/运行/取消状态与装载超时 |
| `network/dev_session.gd` | 每连接命令序号、确认缓存与独立事件缓冲，可绑定已有控制器 |
| `network/world_snapshot.gd` | 公共单位状态加接收者自己的资源、战绩及受控实体标识 |

命令不能指定控制实体或席位，由已握手连接决定。第二名玩家使用 `player_2`，第一名使用 `player`；快照 `controlled_entity` 告诉客户端自己的英雄，另一名英雄进入批量单位视图，不替换自己的 HUD。

伤害奖励按来源拥有者记录，死亡统计进入受害者账本。召唤物标识包含英雄 ID，补刀归召唤者。震击显式传入施法者，避免扣错玩家资源。商店位置按阵营镜像，不能在敌方基地购物。

公共战斗只推进一次，双方控制器分别推进收入、召唤和移动订单，避免连接数增加导致双倍速度。双方快照使用同一 tick，公共单位属性相同；装备、金币、命令确认和个人结算各自独立。

死亡经验由共享世界统一收集符合条件的英雄后分配，避免各玩家控制器抢占死亡标记。已在四英雄规则世界验证同队分摊与私有补刀金币，详见 m2-progression.md；默认模式仍每队一人，四席模式每队两人，中立单位和正式奖励公式尚未实现。

## 胜负与断线

基地摧毁产生公共胜负，双方结束时间和胜方一致，装备与战绩各自独立。结束后拒绝操作。

运行中一人断线仅停止其英雄当前订单，不销毁另一人的世界。留场英雄仍可受击、死亡及复活，已有召唤物按原寿命运行。仅持本局随机凭据的客户端可以在保留期内恢复原席位，详见 m2-reconnect.md；尚无机器人接管或逃跑判负。最后一人主动离场且没有可恢复席位时释放世界；全员意外断线则暂停模拟并保留至重连期限结束。

开局前有人退出则取消本局；人数不足时持续等待并保持心跳，满员后最多等待 30 秒装载。取消状态通过独立状态包通知客户端，客户端关闭连接并提示返回；所有连接释放后才能创建新局。暂不支持装载期间补位。

就绪按已握手连接绑定席位，重复发送不重复计数。开局前命令被拒绝且不消费命令序号或金币。等待期间快照 tick 仍递增以维持有序传输，实际游戏时间 `elapsed` 从全员就绪后开始。公开席位表不包含传输连接 ID。席位表和网络已支持两席、四席或十席；十席仅完成开发联机验证，完整十人整局未验收。

## 验证

```sh
godot --headless --path game --script res://tests/test_shared_match.gd
python3 tools/test_shared_pair.py --godot /实际路径/Godot
python3 tools/test_shared_pair.py --godot /实际路径/Godot --capture .impeccable/shared-review
python3 tools/check_project.py --godot /实际路径/Godot --network
```

规则测试覆盖共同时钟、唯一模拟推进、越权字段拒绝、两方购买与重复交易、同时召唤、第二玩家施法、补刀/经验/击杀归属、共同胜负、个人统计及断线清理。

三进程测试启动一个服务端和两个客户端，通过鼠标购买、移动与召唤验证双方视图；比较同一 tick 的公共世界摘要，至少三个共同 tick 一致才通过。双方退出后再启动新客户端，确认旧局释放。macOS Apple Silicon 真实双窗口测试取得 27 个共同 tick 的一致结果，并分别保存双方截图。

完整工程回归通过：23 个 Godot 测试脚本、14 个 Python 测试、离线场景及原有四类网络测试，加上双席/四席/十席持续联机、UDP 故障和网络分区验证。本轮使用 macOS 无窗口运行；未新增三平台窗口验收。

## 限制与下一步

尚无平台身份、完整资源包认证、正式内容装载认证、战争迷雾、正式英雄。双席与十席可选存档恢复已另行验证，详见 m2-server-restart.md。组队经验仅完成开发分摊规则。快照包含整个开发世界；Windows、Linux 与 macOS Intel 尚未验收。已有光环表现仍为临时单个效果，不代表完整英雄特效系统。

装载屏障规则测试和三进程测试覆盖清理旧局后的九秒独自等待，验证世界冻结、心跳维持和就绪状态清理。同队经验分配已加入规则层，四席网络与场景测试已经接入，已增加双向 UDP 故障验证，十席持续联机已通过，已加入单席位网络分区与恢复验证，已完成完整胜负长局，双席与十席服务器重启恢复已通过，训练技能升级已接入权威命令和快照（见 m2-skill-upgrades.md），下一步物品配方与合成事务。
