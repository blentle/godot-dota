# 6.83d 内容与还原验收

## 版本基准

`game/content/6.83d/manifest.json` 是版本入口。原始地图确认后记录 SHA-256、文件名、语言、来源和 Warcraft III 运行版本；提取结果与人工修正都保留追踪记录。原版地图用于解析和验证，Godot 运行时加载转换后的资源包。

英雄全集由该地图的可选英雄集合确定，不能套用当前 Dota 2 名单。每个英雄记录稳定 ID、原始对象 ID、中文/英文名、属性成长、攻击间隔、攻击前后摇、弹道、移动与转身、碰撞、视野、技能和天赋外机制（本版本不存在的系统不得混入）。

每个技能记录等级参数、魔法消耗、冷却、施法距离、目标过滤、伤害类型、免疫关系、驱散关系、叠加规则、持续时间、动画/特效与脚本化测试。物品记录配方、商店、价格、使用条件、共享冷却、死亡掉落和特殊叠加。原版怪异行为需要登记并决定是否属于兼容要求。

进度状态：`unverified → sourced → implemented → behavior_verified → visual_verified → accepted`。仅 accepted 计入最终完成数；数据存在不等于英雄可玩。

## UI 95% 的可复现定义

先确定基准分辨率与 Warcraft III 版本。建议 1024×768 为经典布局基准，1920×1080 为宽屏适配基准；是否保持 4:3 内容区由参考图决定。没有基准截图时，此指标记作“未验收”。

测试场景固定英雄、等级、物品、选中单位、血量、时间和相机。覆盖默认 HUD、多选、技能冷却、升级、背包、商店、提示框、计分板、菜单、死亡与选人画面，并覆盖近卫/天灾差异。

| 项目 | 权重 | 测量方法 |
|---|---|---|
| 布局与比例 | 35% | 标注区域边界与锚点；核心区域偏差不超过基准宽高的 1% |
| 图形、材质与色彩 | 30% | 同尺寸叠图、差异热图与人工审核；所有正式资源替换占位图 |
| 字体与信息密度 | 15% | 字号、行高、换行、描边、内容完整性逐场景比对 |
| 交互与动态状态 | 20% | 热键、悬停、选中、冷却、禁用、提示定位的录像与操作验收 |

综合达到 95/100 且所有关键场景通过。不得用平均分掩盖缺失的小地图、技能面板、商店或选人页面；不得把整幅游戏画面像素相似度直接当成 UI 完成度。每项评分须保留标注、检查项和原图，并由用户确认视觉验收。

## 美术工作流

先建立素材台账：source、使用范围、原路径、导出路径、哈希、单位尺度、材质、动画映射、状态。优先验证一名完整英雄、一组地形、一座塔与全套 HUD 的视觉管线，再批量处理。骨骼/贴图/音频转换和地图脚本转译是不同流程。

临时几何体只能用于规则开发，不能作为正式画面交付。用户无现成素材，项目自行检索地图、参考和资源，来源见 sources.md。原版风格与资源尚未验收时，视觉成果需明确标记为临时版本。
