# 训练技能点与技能升级

## 开发规则与边界

三个训练配置共用震击、范围冲击和召唤守卫。为保留已有训练操作，出生时三个技能均为 1 级、技能点为 0；英雄每升一级获得 1 点，英雄等级上限仍为 10。此规则和以下数值仅用于验证机制，不代表 DotA 6.83d 正式英雄。

每次升级消费 1 点，技能最高 4 级；升到技能 2/3/4 级分别要求英雄 2/4/6 级。死亡、对局结束、无点数、等级不足或未知技能会拒绝升级且不扣点；暂停或未选择单位时 UI 不提交。眩晕不限制分配技能点。复活保留技能等级和剩余点数。

| 训练技能 | 1 / 2 / 3 / 4 级效果 | 不随等级改变 |
| --- | --- | --- |
| 震击 | 伤害 80 / 110 / 140 / 170 | 魔法 60、冷却 6 秒、距离 5、眩晕 1.5 秒 |
| 范围冲击 | 伤害 70 / 95 / 120 / 145 | 魔法 70、冷却 8 秒、半径 5 |
| 召唤守卫 | 生命 180 / 240 / 300 / 360；攻击 20 / 28 / 36 / 44 | 魔法 80、冷却 20 秒、寿命 15 秒、最多一个 |

升级不治疗、不回魔、不刷新冷却，也不改变已有守卫；下一次召唤使用新的技能等级。最高英雄等级累计获得 9 点，恰好可将三个训练技能升满。

## 命令与持久化

`skill_training.gd` 负责升级前校验和成长策略，`progression_system.gd` 随英雄升级发点。`training_world.gd` 提供统一命令入口；施法与召唤组件读取等级计算效果。校验通过前不修改点数或等级。

联网新增 `upgrade` 命令，只携带技能名称；客户端不能指定等级、点数或控制其他席位。仍使用权威顺序号和确认缓存，重复序号不会再次升级或扣点。远程门面不做本地预测扣点，等待服务器快照更新状态及禁用原因。

单位存档白名单包含技能等级和点数，恢复前验证等级门槛及“已花点数 + 剩余点数 = 英雄等级 - 1”。恢复字典独立复制，避免世界副本修改原存档。构建号升级至 `m2-network-11`，旧构建存档明确拒绝，不静默迁移。

## 界面

右下方空白指令行改为技能点与三个升级按钮，分别对齐上方 Q/W/E。按钮显示当前与下一级、满级或禁用状态，提示说明拒绝原因；施法按钮提示随等级更新实际效果。复用原 HUD 字体、配色、边框和键盘焦点样式，不增加动画。

按 make-interfaces-feel-better 的检查范围，本轮仅检查 Godot HUD 新增升级行：字号及换行无截断，62×42 点击区域互不重叠，复用现有表面样式，不新增图标或动画；每帧只更新文字与状态，不创建字体资源。未调整整个 HUD 或评估原版还原度。未采用弹窗升级页，以保留战场可见性；未增加升级动画，避免反复分配点数时干扰操作。
