# 开发对局完整胜负长局

## 范围

本切片验证从十席装载屏障到基地摧毁、个人结算、终局冻结和离场清理的闭环。使用现有近战卫兵开发配置，不改变生命值、伤害、无敌标志或规则时间倍率，不通过测试后门宣布胜利。

前五分钟全部测试玩家保持位置，让三路兵线正常运行。此后指定阵营的五名英雄通过正常命令依次攻击三座防御塔和基地；另一阵营继续保持位置。英雄仍可受伤、死亡和复活。这是可重复的非对称测试策略，不代表机器人对战能力、真人竞技、正式地图平衡或 M4 已完成。

## 分层验证

- `tests/full_match_orders.gd`：无副作用的测试命令策略，供规则和真实客户端共用；仅返回攻击或保持位置意图。
- `tests/test_full_match.gd`：十席规则模拟，分别验证近卫、天灾胜利；每局至少五分钟，最多十分钟。校验所有席位的胜方、终局交易拒绝、单位/弹道/金币/时钟冻结、个人结果不漂移及离场释放。
- `tests/full_match_scene.gd`：独立图形客户端运行真实战场和结算界面；五分钟后通过网络提交进攻命令；检查全部个人结果、关闭操作、禁用联网重开，继续接收三秒快照以验证终局冻结。
- `tools/test_shared_pair.py --full-match`：一个服务端、十个独立客户端，比较共同 tick 的世界摘要及最终世界、检查全部席位结果，随后验证新局可以进入等待状态。只保留每秒摘要，避免保存整场全量快照。

## 运行

```sh
python3 tools/test_shared_pair.py --godot .tools/Godot.app/Contents/MacOS/Godot --players 10 --full-match
python3 tools/check_project.py --godot .tools/Godot.app/Contents/MacOS/Godot --full-match
```

终局快速排查可使用 `--full-match --warmup-seconds 0`，直接开始正常推塔；它只能记为终局短测，不能计入五分钟长局验收。该短测已接入 `check_project.py --network`。

统一入口的规则回归自动包含两种胜方的完整长局；较慢的真实十客户端长局由 `--full-match` 单独启用，可与 `--network` 组合。当前长局只支持十席无窗口运行，不接受截图或额外持续运行参数组合。服务端保持正常 60 Hz 规则步长。真实客户端测试有十五分钟总时限，超时必须失败，不能按已运行时长宣告通过。

## 结算界面阻塞与传输收尾

十客户端终局时，每个标签和按钮都新建 `SystemFont`，重复触发系统字体查找。独立十进程测量中，单个结算界面装配耗时 5698～6781 毫秒，首帧到达耗时 5859～7044 毫秒。网络主循环与界面装配共用主线程，长时间阻塞会干扰心跳和数据接收；实跑曾出现离场超时与服务端发送失败。

`session_style.gd` 现在复用进程内字体资源，保持原字体顺序和布局。同样的十进程测量降至装配 129～151 毫秒、首帧 137～155 毫秒。测量工具为 `game/tests/measure_result.gd`；这些数值是本机观察值，不是三平台性能保证，也不能证明所有底层发送失败均已消除。

终局快照降为每秒一次，运行中仍每秒十次；终局场景要求至少收到两份快照并比较冻结状态。离场时取消本席位待发送快照，客户端收到应用确认后再完成 ENet 断开握手。应用确认等待仍为 1.5 秒，传输握手最多另等 1.5 秒，超时关闭不会在测试中被当作确认成功。

### 离场确认

长局联机测试发现：客户端已显示结算，不代表服务器已完成离场确认。旧连接离场后不再占用规则会话，原握手超时检查会立即断开已连接超过五秒的传输，可能丢弃尚未送达的 `left` 确认。新增十秒保持连接的双客户端回归已复现该问题。

服务端现在先释放规则席位和凭据，再保留两秒传输窗口送达确认；窗口内只返回离场确认，不允许旧连接重新加入或执行命令，也不因重复请求延长窗口。多人场景测试要求实际收到确认，不能仅凭客户端进程退出判为离场成功。
