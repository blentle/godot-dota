# 按原始种族配置加载时钟模型

## 目标与方案选择

用户选择方案 2：按种族加载原始模型，取代人族模型加手工替换近卫边框的实现。另一方案是继续替换纹理，成本低但无法证明模型及材质对应。此次修正以原始 UI 配置为依据，范围仅为视觉表现。

## 依据与资源

固定副本的 `ui/war3skins.txt` 指定：NightElf → `UI/Console/NightElf/NightElfUI-TimeIndicator.mdl`，Undead → `UI/Console/Undead/UndeadUI-TimeIndicator.mdl`，Human → `UI/Console/Human/HumanUI-TimeIndicator.mdl`。对应二进制均为 49643 字节，但 Git blob 摘要不同，不能据文件大小判断可互换。

沿用现有下载器及转换器，补齐 NightElf、Undead 模型和递归纹理依赖，记录固定来源及摘要。Human 使用已导入原始模型。Orc 不在当前控制台枚举中，本轮不扩展控制台种类。

## 运行时设计

- 保留 `Clock` 节点路径、1024×768 画布和 (435,-7)–(589,70) 区域。
- `configure_race(race)` 只接受已有 NightElf/Undead/Human 枚举，映射到对应原始 JSON；删除按材质编号 4 替换边框的假设。
- 延用独立透明 SubViewport、原始纹理及模型加载器。先比较三模型网格范围、序列与材质；仅在数据证明一致时共用相机参数，否则分别记录取景依据。
- 相同种族重复配置不重建；切换种族释放旧模型。绑定与配置不得递归互调。失败明确报告并采用已有静态入口，不继续采样不完整模型。
- 保留暂停、恢复、零推进及确定时间点采样；不改变权威状态，不新增真实昼夜周期。原版时刻到动画帧映射继续标为未验收。

## 验证与完成条件

先增加失败回归，覆盖三种族实际 Source 路径、重复配置、跨种族切换、暂停/恢复、重绑、失败绑定保护及规则只读。检查不能只比较设置字段，必须比较实际加载的数据与模型数量。

各模型两段序列分别截取 0/15/30 秒；完整近卫、天灾 HUD 另做实机截图，检查裁剪、透明和重复边框。运行相关专项、整工程回归、来源摘要及 500 行检查；实现与视觉记录分模块本地提交，不自动推送。

完成基础模型对应不代表 Warcraft III 1.26 像素验收。种族完整控制台、精确混合、实际昼夜时间映射和 Windows/Linux 实机仍分别记录边界。
