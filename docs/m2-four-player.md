# 四玩家 2v2 开发联机

共享开发服务器支持两席或四席；默认为两席。四席模式按握手顺序分配近卫、天灾、近卫、天灾，控制权来自连接绑定。所有客户端仍使用训练角色与开发数值，不属于正式英雄验收或十人对战。

## 启动和验证

启动服务端：

```sh
godot --headless --path game --script res://tests/network_server.gd -- --port=27883 --shared --players=4
```

分别启动四个客户端，各执行一次：

```sh
godot --path game -- --connect-local=27883
```

自动测试使用一个服务端与四个独立客户端进程；客户端执行真实战场装配和操作流程，可在无窗口模式运行：

```sh
python3 tools/test_shared_pair.py --godot /实际路径/Godot --players=4
python3 tools/check_project.py --godot /实际路径/Godot --network
```

可加 `--capture 输出目录` 打开实际窗口并保存每个席位截图。无窗口运行不能作为窗口视觉或三平台验收。

## 权威边界

- 欢迎包分别提供 `slot`、`team`、`entity` 和 `required_players`，席位编号不再充当阵营编号；构建标识更新为 `m2-network-6`。
- 同队英雄在己方基地分散出生，各出生点均处于购物范围并可导航离开。新局保留服务器人数配置，清空连接与就绪状态。
- 所有席位就绪后才推进世界；少于四席时四人局不启动。超时和开局前断线仍取消整局，开局后不能接管断线席位。
- 传输容量保留额外握手空间，用于返回满员错误；实际游戏席位仍严格限制为配置人数。
- 金币、背包、命令序号和控制英雄按连接隔离；经验使用统一同队分摊规则。公共战斗、兵线和弹道每步只推进一次。

## 测试内容

`test_shared_seats.gd` 验证四席分配、阵营、出生点、购物范围、未满员冻结、第五席拒绝、重复购买、伪造席位拒绝、第三席控制隔离、断线留场和新局配置。

通用多人场景脚本验证每个客户端控制服务端指定的独立英雄、看到所有其他英雄、各自购买后只持有一件装备、独立移动以及所有召唤物出现。测试工具核对席位无重复、阵营分配正确，并要求所有客户端至少三个共同 tick 的公共单位摘要一致。所有客户端退出后，新客户端独自等待九秒，验证旧局清理及新局不会提前开始。

## UDP 故障注入

已增加 `--impaired` 参数，在每个客户端和服务器之间注入双向数据报故障；首轮 macOS 无窗口验证获得 82 个共同 tick 的一致结果，详见 [故障模型与边界](m2-network-impairment.md)。该结果不作为互联网性能或三平台验收。

## 后续缺口

仍需十席扩展与长局测试、更多网络故障模型与掉线重连、战争迷雾、正式内容校对以及平台身份与匹配。当前仍仅监听本机回环地址；正式服务器入口未开放。Windows、Linux 与 macOS Intel 尚未验收。
