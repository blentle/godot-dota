# 经典旧式模型粒子

本轮继续英雄外观还原，补齐已导入模型中 15 个旧式 `ParticleEmitter` 的基础显示。它们抛出独立 MDX 网格，与 `ParticleEmitter2` 的精灵头尾不同。涉及奇美拉、风蛇、麦迪文、蝙蝠骑士及黑曜石雕像外观；不代表这些英雄的正式规则已经完成。

## 原始资源

依赖解析器递归读取 `ParticleEmitters[].Path`，沿用地图优先、固定经典副本兜底。新增 9 个原始碎片模型、3 张贴图，包含羽毛、骨骼、内脏和石块；逐项记录固定提交的 Git blob 摘要，转换前重新验证。当前完整记录为 1564 项来源、1352 张二次幂 PNG。未执行地图脚本。

下载器改为通过 curl 参数调用遵守系统代理，不拼接 shell 命令；摘要不符仍拒绝转换。保留既有清单顺序，新增依赖追加，便于审查。

## 表现与边界

- `model_particles.gd` 只负责表现，每个父模型最多保留 64 个碎片模型实例，按资源路径复用。按需创建后保留池，重绑释放旧实例。
- 以 60 Hz 子步读取原始可见性、发射率、寿命、速度、纬度和重力。通过独立骨骼取样捕获短暂死亡窗口，不改写可见 Skeleton。
- 碎片出生后在世界空间移动，不随父单位位移；原始坐标变换只应用一次。播放子模型第一段序列，寿命结束隐藏回收。
- 超出容量或超过两秒追赶窗口会丢弃并计数。暂停和零推进不发射。
- 子模型不递归创建发射器，避免资源引用环。本次九个原始碎片均无子发射器；后续若引入带子特效的资源，应另行设计有界嵌套。

经度、重力积分、随机朝向、特殊骨骼继承标志与精确缩放仍待 Warcraft III 1.26 逐帧核对。此处属于基础接入，不是像素或行为完全一致的验收。单位根节点在单帧内的移动尚未插值；普通 ParticleEmitter2 的出生骨骼子步已补齐，见 [粒子说明](classic-particles.md)。

## 验证

`test_classic_model_particles.gd` 用原始奇美拉 Death 验证短窗口生成、第一序列、无递归发射、世界空间、缩放、寿命、池复用、总容量、长帧限制及重绑。全英雄冒烟额外比较旧式发射器数量与源配置。

本轮工程统一回归、214 个英雄身体/头像模型加载、资源摘要检查及源码行数检查通过。没有追加十客户端图形压力或网络故障测试。

macOS Apple Silicon 真实渲染检查：Death 初始 0 个碎片，0.45 秒有 27 个，截图可见原始紫色羽毛及骨骼碎片。训练地形、树和建筑仍是占位；不能据此认定整体画面还原完成。Windows、Linux 尚未实测。

复现：

```sh
.tools/Godot.app/Contents/MacOS/Godot --path game --script res://tests/capture_classic_motion.gd -- --classic-hero=E00P --classic-action=Death --classic-zoom=12 --capture-prefix=/tmp/classic-chimaera-death
```
