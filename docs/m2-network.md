# 双进程网络适配切片

本文介绍默认独立训练会话。新增的 `--shared` 同局双玩家模式及差异见 [共享对局说明](m2-shared-match.md)。

当前交付是本机回环的开发验证，最多四个连接各运行一个独立训练世界；这些连接不在同一局：独立 Godot 服务端推进三路训练世界，图形客户端可通过专用参数发送操作并显示服务器快照。默认启动仍为离线选人。不能据此宣称十人对战、正式服务器或 M2 全部完成。

## 运行

指定 Godot 4.7.2 可执行文件，运行自动验证：

```sh
python3 tools/test_network_pair.py --godot .tools/Godot.app/Contents/MacOS/Godot
godot --headless --path game --script res://tests/test_network_authority.gd
godot --headless --path game --script res://tests/test_remote_world.gd
python3 tools/test_network_pair.py --godot .tools/Godot.app/Contents/MacOS/Godot --scene
python3 tools/test_network_pair.py --godot .tools/Godot.app/Contents/MacOS/Godot --concurrent
python3 tools/test_network_pair.py --godot .tools/Godot.app/Contents/MacOS/Godot --anomaly
```

其他系统把 `--godot` 改为实际可执行文件路径。脚本自动选择本机 UDP 端口，等待服务端就绪，先后启动两个客户端进程，确认退出后席位释放、第二次连接获得全新世界；超时或验证失败会报错，最终回收自己启动的服务端。端口选择存在操作系统释放与绑定间的竞争，冲突会明确失败。

手动运行时分别打开两个终端，启动开发服务端和可操作的图形客户端：

```sh
godot --headless --path game --script res://tests/network_server.gd -- --port=27883
godot --path game -- --connect-local=27883
```

图形入口固定使用近战卫兵；连接失败、席位占用及连接中断会显示状态页，并可返回离线选人。联网菜单只阻止本地操作，不暂停服务器；退出菜单可恢复操作，返回选人会断开连接。联网结算可返回离线选人，尚不能直接重开联网局。

`network_client.gd` 保留为无界面自动验证入口。普通 `--server` 仍拒绝启动，防止误认为已具备部署能力。自动场景测试的 `--scene --capture .impeccable/review` 会打开真实窗口并保存联网战场、断线页截图；测试服务端在连接后二十秒主动退出，用于验证失联处理。

| `network/dev_protocol.gd` | JSON 解码、字段与类型白名单、版本身份 |
| `network/dev_authority.gd` | 连接握手、独立会话分配及释放 |
| `network/dev_session.gd` | 每会话规则世界、命令序号、固定步模拟与事件缓冲 |

| `network/world_snapshot.gd` | 从规则世界提取独立值快照与战斗事件 |
| `network/dev_server.gd` | ENet 收发、连接超时、流量限制、定期快照 |
| `network/dev_client.gd` | 发送命令、接收与保存最新快照，不运行规则模拟 |

## 当前契约

服务端仅绑定 `127.0.0.1`，最多接受四个传输连接，每个通过握手的连接独占一个训练世界。握手包含协议版本、开发构建标识、清单文件 SHA-256 和开发角色 ID；清单哈希不是完整资源包校验，也不构成认证。成功后连接绑定本会话 `player` 控制权，不能操作其他会话。重复握手被拒绝；开发比赛标识仍是固定值，不是正式比赛身份。

命令包含 `type=command`、固定开发比赛标识、从 1 开始的连续 `sequence`、`command` 与可选 `target`。支持移动、攻击、停止、保持、三种训练施法、购买和出售，全部调用已有规则入口；不允许客户端传入控制实体、伤害或金币。移动坐标校验类型、有限值和地图边界。

每个合法命令序号只执行一次；最近一次重复序号返回缓存确认，过期或跳号拒绝。格式校验失败不占用序号；规则层拒绝的合法命令占用序号并返回原因。最近确认只缓存一条，重复包即使更换载荷也不会再次执行。

服务端启动时显式使用 60 Hz 物理帧率，权威规则每步推进 1/60 秒，每六步发一次全量快照；离线场景仍使用工程配置的 30 Hz。目前命令、确认和快照均用可靠 ENet 通道。快照包括 tick、确认序号、单位属性、状态与冷却、弹道（含目标与速度）、金币、装备、波次、召唤物和结算，以及服务端提供的购买/技能可用性和本窗口内的战斗事件。事件只保留序号、类型、发起者、目标、生命代次、数值与坐标白名单字段，坐标序列化为数组；单个快照窗口最多携带 64 条，超出丢弃新事件，并在快照 `dropped_events` 中累计记录；这是有损视觉事件缓冲，不承诺完整事件回放。客户端拒绝旧 tick，不预测命中或本地扣费；等待确认期间有最多 32 条待确认命令的限制。此频率为开发验证值，不是最终性能预算，实际墙钟推进速度受模拟负载影响。

客户端表现层只做显示平滑：单位位置在上一个显示位置与快照位置之间按快照间隔（1/10 秒）插值，首次出现、生命代次变化、死亡状态改变或超过 12 世界单位的位移立即就位；近距离复活也不会滑行。弹道最多外推一个 0.1 秒窗口，目标死亡或生命代次变化后停止外推；快照到达时回到权威位置。战斗事件按单调序号去重，过滤过期生命代次，在快照状态更新后转发给表现层，驱动受击闪烁、挥砍动作、技能光环和死亡提示；全部只影响显示，不推进任何规则。快照未覆盖整个窗口的极端情况下，单位会在快照位置短暂停留等待下一包。

单个入站命令最大 4096 字节，每连接每秒最多 120 包，每次物理帧最多处理 128 包。超限连接断开；握手最长五秒，十秒没有入站消息也断开。图形客户端每秒发送心跳，五秒未收到服务器消息后冻结战场、关闭输入并显示断线提示。拥有者断开即销毁开发世界；下一次连接创建新世界，不属于重连恢复。客户端关闭后忽略迟到快照，不能自动恢复操作。

树木布局独立于渲染生成，服务端和图形场景使用相同固定坐标；服务器导航同时拥有树木和建筑障碍。远程门面的 `block` 只记录小地图显示数据，不创建寻路或战斗规则。

## 验证结果与缺口

已在 macOS Apple Silicon / Godot 4.7.2 上通过：

- 规则测试：错误版本、席位冲突、跨连接控制、额外字段、跳号、重复扣费、旧序号、异常坐标、业务失败确认、快照隔离、断开清理，以及事件缓冲、捕获后清空、白名单序列化与单窗口上限。
- 两个真实进程：拒绝错误版本、合法握手、购买、重复购买只扣一次、移动命令改变服务端位置、连续快照，以及第二客户端进程重新进入全新世界。
- 远程门面规则：没有本地移动、扣费或施法模拟；验证库存、派生属性、冷却、召唤、弹道、旧快照拒绝、服务器树木阻挡、快照窗口内单位插值、弹道外推与事件转发。
- 独立服务端加真实图形窗口：鼠标购买、HUD 装备更新、远程移动、召唤物视图与事件驱动的技能光环、菜单打开仍收快照、十一秒无操作心跳保活、服务端退出后的冻结与返回离线选人；完成两张截图检查。
- 离线选人/结算、训练场、兵线场景、商店和技能交互回归。
- Python 工具回归与全仓库源码行数检查。

已完成两个独立会话并发测试，以及每帧人为延迟 180 毫秒、客户端停止读取 2.5 秒、命令突发与 32 条待确认上限测试。慢服务器和停读不是网络丢包注入，不能替代真实网络故障验证。

仍缺同一世界多玩家、网络层延迟与丢包测试、增量快照、带宽/慢客户端控制、正式内容包握手、十人身份、装载屏障、重连和战争迷雾。单位位置已按快照间隔插值、弹道按目标外推；完全发生在单个快照窗口内、未出现在任何快照中的弹道仍无法呈现。开发快照包含整个训练世界，不能用于正式联网对局。Windows 与 Linux 尚未实测。

网络表现平滑与战斗视觉事件已交付；下一步实现同一世界两名受控玩家及各自视图，再逐步扩展到十人。

传输 API 参考：[Godot ENetMultiplayerPeer](https://docs.godotengine.org/en/stable/classes/class_enetmultiplayerpeer.html)、[Godot MultiplayerPeer](https://docs.godotengine.org/en/stable/classes/class_multiplayerpeer.html)。
